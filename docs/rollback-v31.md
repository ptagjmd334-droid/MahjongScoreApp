# v31保護版への復元手順（M8 v32の自動開発トライアル）

## 復元ポイント
- 開発着手前の main commit: `fb72058983f6370464a542008ac6cff4554d1e8c`
- 同じ内容を保持する保護ブランチ: `backup/v31-before-auto-m8`
- 試験実装ブランチ: `work/m8-stability-yaku-after-v31`
- v31→v32は原則 GitHub Pagesの公開元である `main` をfast-forwardで進める。v31保護ブランチは変更しない。

## ユーザーが「v31へ戻して」と依頼した場合
1. 現在のmain SHAを読み、予定外の他者コミットが無いか確認する。
2. `backup/v31-before-auto-m8` のSHAが上記v31 SHAと一致することを確認する。
3. v32の結果を保管したい場合は現在mainから別のバックアップブランチを作る。
4. ユーザーの明示的な復元指示がある場合のみ、GitHubのmain refを `fb72058983f6370464a542008ac6cff4554d1e8c` に戻す（GitHub API update_ref forceが必要になる場合がある）。同時編集があれば一旦停止し調整する。
5. GitHub Pagesの該当SHAデプロイ成功を確認。Safari/PWAのキャッシュが以前のHTMLを表示し続ける場合は、公開URLを一度開いてからアプリを再起動する。
6. v32で追加した履歴などのlocalStorageキーはv31から参照しない。既存の試合・途中入力の保存キーは消さない。

## 範囲と限界
この復元で戻るのは **GitHub上のアプリコードおよび新規文書・CI設定**。ユーザー端末の対局データを巻き戻すものではない。iPhone内部で保持されたキャッシュはGitHubのbranch操作だけでは即座に切り替わらない場合がある。

## 自動検証の範囲
Nodeで手役/符の純粋関数を単体テスト、読込対象スクリプトの構文チェック、GitHub Actions上のChromium横画面で初期設定→ロン→和了者→放銃者→点数表→判定情報の開閉とDOM増殖の簡易検査。iOS WebKit特有のメモリ制限と実牌・実卓精度はこれだけでは再現しない。
