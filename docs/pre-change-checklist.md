# MahjongScoreApp 変更前チェックリスト

新機能追加・バグ修正の **前に毎回読む短縮版**。
詳細は `docs/known-mistakes-and-prevention.md` を参照。

## 0. ユーザー指定ルール
- [ ] `docs/user-development-rules.md` を確認した
- [ ] 決定済み仕様をユーザーへ再質問していない
- [ ] バグ修正なら、元々予定していた次機能も同じ版で進めるか確認した
- [ ] テストは小出しではなく、連続で一気に実施できる形を考えた

## 1. 変更対象の確認
- [ ] GitHub main の最新対象ファイルを取得した
- [ ] index.html の現在の読込順を確認した
- [ ] 同じUI/状態を触る旧パッチが他にないか確認した
- [ ] 古いパッチを外すなら、そのファイルの別責務を洗い出した

## 2. 原因を言語化
- [ ] 症状を1文で言える
- [ ] 根本原因を「DOM / state / rule / lifecycle / cache / deploy」のどれかに分類した
- [ ] 原因が未確定なら、推測のまま直さず切り分けを先にした
- [ ] ユーザーへ「なぜ起きたか」を説明してから/同時に修正する

## 3. iPhone/PWA
- [ ] `vw/dvh` だけで位置を決めていない
- [ ] fixedモーダルの祖先にtransformがない、またはbody直下
- [ ] scroll領域とfooterがDOM上でも分離されている
- [ ] pageshow / visibilitychange 対応が無限タイマー化していない
- [ ] カメラを触る変更なら全離脱経路でMediaStreamをstopする

## 4. Observer/性能
- [ ] MutationObserver callbackが、自分の監視対象を変更して再発火しない
- [ ] body全体のattributes/characterData監視を安易に使っていない
- [ ] 追加ボタン/装飾は毎回remove→createせず、可能なら再利用
- [ ] 点数表を30秒放置しても白画面/ラグが出ない

## 5. 麻雀判定データ
- [ ] 14枚のSource of Truthがどこか明確
- [ ] 和了牌を保持している
- [ ] 門前/副露を保持している
- [ ] ロン/ツモ・和了者・放銃者を正しく引き継ぐ
- [ ] ポン/明カン/暗カンなど面子内訳が必要な計算で欠けていない
- [ ] nullが「未判定」「複数候補」「エラー」のどれか区別できる

## 6. 保存・復旧
- [ ] 新しく追加した重要stateは再読み込み後も復元できる
- [ ] 入力途中復旧で計算元データも戻る
- [ ] 青の翻 / 橙の符 / 緑の推奨はDOMだけに依存していない
- [ ] Undo/クラウド同期に影響するstateか確認した

## 7. デプロイ
- [ ] 新ファイルを作っただけでなくindex.htmlから読み込んでいる
- [ ] 最新版だけがbuild badgeを書き換える
- [ ] 動的script挿入で旧版が後から読み込まれない
- [ ] cache-bust queryを更新した
- [ ] GitHub Pages最新workflowのhead SHAが最新commitと一致
- [ ] Safari直URLとPWAの両方で版数確認

## 8. 変更後の最低回帰
変更内容に該当するものだけ実施。
- [ ] アガリ→ロン/ツモ→和了者→放銃者→点数表
- [ ] 点数表scroll・最下部3ボタン
- [ ] 4方向プレイヤー選択
- [ ] 戻る/キャンセルで点数・局・本場・供託が変わらない
- [ ] 符・翻・推奨セル
- [ ] カメラ終了後にiOS緑インジケータが消える
- [ ] 入力途中復旧でM8状態も戻る
- [ ] 既知の対象カテゴリで再発がない

## 9. 記録
- [ ] 新しいユーザールールが出たら `user-development-rules.md` に追加
- [ ] 新しいミスなら `known-mistakes-and-prevention.md` に追加
- [ ] 作業終了時、ユーザーが作業時間を明示したら `development-time.md` を更新
